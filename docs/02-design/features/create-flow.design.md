## 0. Context Anchor

| Key | Value |
|---|---|
| **WHY** | 자유 발화에서 시작해 사용자의 말을 존중하는 이야기 지도까지 이어지는 제품의 핵심 체험이다(§1, §2, §4). |
| **WHO** | 창작 입문자와 공모전 준비생. 빈 캔버스나 전문 구조 용어보다 말하기로 시작하려는 사용자다(§4, H-A/H-F). |
| **RISK** | 앞 단계에서 사용자의 말을 지우거나, AI가 후크를 대신 만들거나, 검증되지 않은 휴리스틱 결과를 AI 성능처럼 보이면 소유감·신뢰·차별화 축을 잃는다(P1/P2/P3, §5). |
| **SUCCESS** | 사용자가 1단계에서 자유 텍스트 또는 음성으로 시작해, 2단계의 빈칸 질문(최대 10개), 3단계의 로그라인 3안 선택, 4단계의 사용자 후크 입력을 거쳐, 5단계의 24칸 가로 이야기 지도를 확인하고 어느 완료 단계로든 되돌아가도 기존 산출물을 잃지 않는다(§4, P3). |
| **SCOPE** | `/create`의 5단계 상태 전이, 화면·입력·API 연결, 무키 데모 경로, 24블록 타임라인. 계정·서버 저장·내보내기·스토리툰 생성·결제·i18n은 제외한다(§4, §6, §11). |

## 1. 기능 요구사항

**갭 분석의 대조 단위다.** 한 줄에 하나씩, 검증 가능하게 쓴다.

| ID | 요구사항 | PRD 근거 | 우선순위 |
|---|---|---|---|
| R1 | 사용자가 `/create`에 진입하면 질문지를 먼저 보여주지 않고, 자유 텍스트 입력과 선택적 음성 입력으로 아이디어를 시작하게 한다 | §4 1단계, H-A | P0 |
| R2 | 사용자가 1단계에 발화를 제출하면 2단계로 이동하고, 발화에서 확인된 요소와 비어 있는 요소만 구분하여 표시한다 | §2, §4 1·2단계, §5 | P0 |
| R3 | 2단계에서 비어 있는 요소가 있으면 한 화면에 질문 하나만 표시하고, 질문 수는 10개 이하로 제한한다 | §4 2단계, §3 H-C | P0 |
| R4 | 2단계에 장면이 있으면 장면 원문을 유지한 채 이야기 흐름에서 가능한 후보 위치를 보여준다 | §4 2단계, §5 | P1 |
| R5 | 2단계의 질문이 끝나거나 질문이 없으면 사용자의 발화·추출 요소·답변으로 3단계의 로그라인 세 안을 만든다 | §4 2·3단계 | P0 |
| R6 | 3단계는 정공법·관계·아이러니처럼 서로 다른 갈등·결말 방향의 로그라인 3안을 보여주고, 각 안의 참고 벤치마크를 함께 보여준다 | §4 3단계, §7 | P1 |
| R7 | 사용자가 로그라인 한 안을 선택하면 선택된 방향을 유지한 채 4단계로 이동하고, 이전 단계로 돌아가 선택을 바꿀 수 있다 | §3 P3, §4 3·4단계 | P0 |
| R8 | 4단계에서 사용자는 인물·사건·흐름에 대한 심화 메모를 직접 입력할 수 있다 | §4 4단계 | P1 |
| R9 | 후크·나만의 차별점은 사용자가 직접 입력한 값만 확정하고, AI가 비어 있는 후크를 자동으로 채우지 않는다 | §3 P1, §4 4단계, §7 | P0 |
| R10 | 4단계에서 이야기 지도를 요청하면 5단계에서 4막·24칸 가로 타임라인으로 결과를 보여준다 | §3 H-F, §4 5단계 | P0 |
| R11 | 1~4단계의 화면과 안내 문구에는 초보자가 이해할 수 있는 표현을 사용하고, 24블록·B스토리 등 전문 용어는 5단계 지도에서 처음 노출한다 | §4, §7의 초보자용 구조화 흐름 | P1 |
| R12 | 현재 결과의 생성 경로가 휴리스틱·mock이면 그렇게 표시하고, 실키 경로가 검증되지 않았음을 숨기거나 결과를 검증된 AI 성능으로 홍보하지 않는다 | §3 P2, §4 대외 표기 규칙, §11 | P0 |
| R13 | 사용자가 완료한 어느 단계에서든 이전 단계로 이동할 수 있고, 이동만으로 하위 단계의 답변·선택·심화 메모·후크·이야기 지도를 삭제하지 않는다 | §3 P3 | P0 |
| R14 | 5단계에서 이야기 지도를 확인한 뒤에도 같은 프로젝트를 작업실·서재에서 이어서 다룰 수 있도록 결과를 남긴다 | §4, §9 | P1 |

## 2. 비목표 (Non-goals)

- 1단계에서 구조화된 항목이나 질문지를 먼저 입력받는 것 — 자유 발화가 시작점이다(§4 1단계, H-A).
- 2단계에서 발화에 없는 설정을 AI가 보완하거나 후크를 대신 쓰는 것 — P1과 §5의 근거 없는 값 생성 방지에 어긋난다.
- 로그라인 3안이 사용자에게 최적이라는 것을 확정하는 것 — 3안은 H-E 검증 전의 제품 가설이다(§3-2, §8 H3).
- 4막·24블록이 초보자에게 우월하다고 주장하는 것 — 24블록 자체는 미검증이며 H-F의 검증 대상이다(§3-2).
- 5단계 전에 전문 방법론을 학습시키는 것 — 초보자용 텍스트 구조화 흐름을 유지하고, 전문 지도는 결과 확인 시점으로 미룬다(§4, §7).
- 계정·서버 저장, 프로젝트 내보내기·가져오기, 스토리툰 생성, 결제, 스트리밍, i18n을 포함하는 것 — 현재 6일 데모와 `/create` 5단계 범위 밖이다(§4, §6-2, §11).

## 4. API 명세

**3자 대조 대상이다** — 이 표 ↔ 서버 라우트 ↔ 클라이언트 호출이 전부 일치해야 한다.

### `POST /api/extract`

| 항목 | 값 |
|---|---|
| 요청 | `{ utterance: string }` |
| 응답(성공) | 추출 요소, 빈칸 질문 목록(최대 10개), 실제 엔진 경로. 요소의 의도 형식은 `extraction.design.md` R2의 4종 메타데이터를 따른다 |
| 응답(실패) | 400 입력 오류 또는 500 처리 오류 |
| 모델 사용 | 실키 경로는 `MODEL_LIGHT`; 무키 경로는 사용하지 않음 |
| 무키 폴백 | 있음 — 휴리스틱 추출. 데모는 무키 경로로 촬영한다(§4, §11) |
| 호출하는 곳 | `app/create/page.tsx:133-147` |

### `POST /api/scene-blocks`

| 항목 | 값 |
|---|---|
| 요청 | `{ sceneText: string }` |
| 응답(성공) | `{ candidates: SceneCandidate[], benchmarks: Benchmark[] }` — 입력 장면을 유지하고 가능한 흐름 위치 후보를 반환한다 |
| 응답(실패) | 잘못된 JSON·입력은 400, 분석 실패는 500 |
| 모델 사용 | 실키 경로는 `MODEL_MAIN`; 무키 경로는 휴리스틱 |
| 무키 폴백 | 있음 — 후보·유사 참고 작품을 휴리스틱으로 반환한다 |
| 호출하는 곳 | `components/ScenePlacement.tsx:68-73` |

### `POST /api/loglines`

| 항목 | 값 |
|---|---|
| 요청 | `{ utterance: string, elements: ExtractedElements }` |
| 응답(성공) | `{ options: [LoglineOption, LoglineOption, LoglineOption] }` — 각 안은 로그라인·premise·direction·benchmarkTitle·reason을 가진다 |
| 응답(실패) | 발화와 요소가 모두 없으면 400, 생성 실패는 500(모델 거부는 422) |
| 모델 사용 | 실키 경로는 `MODEL_MAIN`; 무키 경로는 사용하지 않음 |
| 무키 폴백 | 있음 — 템플릿과 휴리스틱 벤치마크로 3안을 만든다. 실키 경로도 부족한 안은 mock으로 보충한다 |
| 호출하는 곳 | `app/create/page.tsx:161-170` |

### `POST /api/generate`

| 항목 | 값 |
|---|---|
| 요청 | `GenerateInput`와 pipeline 실행 플래그. 클라이언트는 `sessionToGenerateInput(session)` 결과를 전송한다 |
| 응답(성공) | `{ story: Story, issues: ValidationIssue[], engine: string, mode: "pipeline" }` — 이야기 지도는 24개 블록을 가진다 |
| 응답(실패) | 로그라인이 없으면 400, 생성 실패는 500 |
| 모델 사용 | 실키 경로는 `MODEL_MAIN`; 무키 경로는 mock 생성기 |
| 무키 폴백 | 있음 — 4막·24블록 구조 골격을 반환한다(§4, §11) |
| 호출하는 곳 | `app/create/page.tsx:183-203` |

### `GET /api/benchmark` (보조)
| 항목 | 값 |
|---|---|
| 요청 | 없음 |
| 응답(성공) | `{ list: [{ title: string, posterUrl: string \| null, ... }], tmdb: boolean }` |

## 6. 원칙 준수 (PRD v3 §3)

| 항목 | 이 기능에서의 의미 | 지키는 방법 |
|---|---|---|
| P1 후크는 사람 | 후크는 사용자가 자신의 차별점을 남기는 지분이며, 자동 생성 대상이 아니다 | 4단계에 별도 후크 입력을 두고 생성 입력에는 사용자가 입력한 후크만 전달한다 |
| P2 정직한 표기 | 무키 mock/휴리스틱 결과와 검증되지 않은 실키 결과를 구분해야 한다 | 결과·장면 배치·추출 메타데이터에 실제 엔진을 표시하고, 데모는 휴리스틱 상한임을 명시한다 |
| P3 되돌아갈 자유 | 사용자가 2단계 답변이나 3단계 선택을 다시 고치고도 이후 작업을 잃지 않아야 한다 | 완료/현재 단계 내비게이션을 제공하고, 단계 이동만으로 세션의 하위 산출물을 초기화하지 않는다 |
