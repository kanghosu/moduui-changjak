## 0. Context Anchor

| Key | Value |
|---|---|
| **WHY** | 사용자가 자유롭게 쏟아낸 말을 존중하면서, 이미 말한 요소를 다시 묻지 않는 것이 제품의 유일한 차별화 축이다(§2). |
| **WHO** | 창작 입문자와 공모전 준비생. 질문지를 먼저 작성하기 어려운 사용자다(§4, H-A). |
| **RISK** | 발화에 있는 주인공·장면 등을 놓치거나 근거 없이 채우면 반복질문과 무근거 생성이 발생하고, 제품의 차별화 축과 소유감이 함께 무너진다(§5, P1). |
| **SUCCESS** | 입력 발화의 요소마다 값·원문 근거구간·신뢰도·모름 상태를 보존하고, 근거구간 또는 모름 상태가 있는 요소는 질문 목록에서 제외하며, 어떤 발화에서도 질문 수가 10개 이하이면 성공이다(§5, H-C). |
| **SCOPE** | `POST /api/extract`의 추출·빈칸 질문 계약, 실키/무키 경로, 2단계 질문 화면과 추출 결과 데이터 모델. 로그라인 생성과 24블록 지도 생성은 포함하지 않는다. |

## 1. 기능 요구사항

**갭 분석의 대조 단위다.** 한 줄에 하나씩, 검증 가능하게 쓴다.

| ID | 요구사항 | PRD 근거 | 우선순위 |
|---|---|---|---|
| R1 | 사용자가 자유 발화를 제출하면 발화에 실제로 존재하는 이야기 요소만 추출하고, 없는 설정을 창작하거나 보완하지 않는다 | §4 대외 표기 규칙, §5 | P0 |
| R2 | 발화에서 요소를 추출하면 각 요소를 `값 + 원문 evidence span + 신뢰도 + 모름 상태`로 저장한다. **현재 코드: `ExtractedElements`가 문자열만 저장하므로 R: 미구현** | §5 | P0 |
| R3 | 요소에 원문 근거구간이 있거나 사용자가 모름을 명시하면 그 요소를 “이미 말한 것”으로 판정하여 해당 요소 질문을 생성하지 않는다 | §2, §5, H-B | P0 |
| R4 | 발화에 근거구간도 모름 상태도 없는 요소가 있으면 그 요소만 질문 목록에 넣고, 한 화면에 질문 하나를 표시한다 | §4 2단계, §5 | P0 |
| R5 | 질문 목록을 생성하면 어떤 입력에서도 최대 10개로 제한한다. **현재 상한 강제 위치: `engine/creation.ts:49,52-56`** | §3 H-C, §4 2단계, §5 | P0 |
| R6 | 사용자가 질문에 “없음” 또는 “모름”으로 답하면 해당 요소를 임의의 값으로 저장하지 않고 모름 상태로 기록한다 | §5 | P0 |
| R7 | 장면이 발화에 있으면 사용자의 장면 표현을 원문 근거구간으로 보존하고, 장면의 내용을 잘라내거나 결말을 새로 만들지 않는다 | §4 2단계, §5 | P1 |
| R8 | `ANTHROPIC_API_KEY`가 없을 때도 발화 제출부터 빈칸 질문 생성까지 동일한 추출·질문 계약을 제공하되, 휴리스틱의 품질을 실제 모델 품질로 표시하지 않는다 | §4 대외 표기 규칙, §11 | P0 |
| R9 | `ANTHROPIC_API_KEY`가 있을 때도 실제 발화에 있는 내용만 추출하고 사용자 표현을 최대한 보존하며, 모델 경로가 검증되지 않았다는 사실을 숨기지 않는다 | §4 대외 표기 규칙, §5 | P1 |
| R10 | 추출 결과를 사용자에게 표시할 때 휴리스틱·실제 모델 등 생성 경로를 실제 경로와 일치하게 표기하고, 휴리스틱 결과를 “AI가 만든 결과”라고 표기하지 않는다 | P2, §4 | P0 |
| R11 | 요소별 precision·recall·F1, 근거구간 포함률, 누락률, 근거 없는 값 생성률과 반복질문률을 골드셋으로 측정할 수 있도록 요소별 근거와 상태를 남긴다 | §5, §8 H5 | P1 |

## 2. 비목표 (Non-goals)

- 자유 발화만으로 완성된 로그라인·스토리 지도·스토리툰을 만드는 것 — extraction은 2단계의 재료 확인과 빈칸 질문까지만 담당한다(§4).
- 발화에 없는 인물·사건·결말을 추론해 채우는 것 — 사용자 소유감과 P2를 해친다(§3 P1/P2, §5).
- 후크를 AI가 대신 확정하는 것 — 후크는 사용자가 채우는 별도 지분이다(§3 P1, §4 4단계).
- “질문 10개가 피로하지 않다”를 검증된 사실로 취급하는 것 — 10은 H-C 검증 전의 고정값이다(§3-2, §8 H2).
- 휴리스틱 또는 실키 경로의 추출 품질을 검증 완료로 주장하는 것 — 실키 경로는 데모 범위 밖이고 실제 모델 품질은 미검증이다(§4, §11).
- 계정·서버 저장·내보내기·가져오기를 구현하는 것 — 저장 전략의 후속 단계이며 이 기능의 추출 계약 범위가 아니다(§6).

## 3. 화면·컴포넌트

| 화면/컴포넌트 | 파일 | 책임 |
|---|---|---|
| 추출 API | `app/api/extract/route.ts` | 발화를 받아 요소를 추출하고 빈칸 질문 목록을 반환한다 |
| 휴리스틱 추출기 | `engine/extract-heuristic.ts` | 무키 상태에서 발화의 근거 있는 요소를 추출한다 |
| 질문·요소 확인 화면 | `components/create/QuestionStage.tsx` | 먼저 잡힌 재료와 한 번에 하나의 빈칸 질문을 표시한다 |
| 추출 응답 경계 | `components/create/createSchemas.ts` | 클라이언트가 추출 응답 형식을 파싱한다 |
| 질문 정책·세션 모델 | `engine/creation.ts` | 요소 키, 질문 풀, 최대 질문 수, 세션 병합 규칙을 정의한다 |
| 장면 배치 보조 | `components/ScenePlacement.tsx` | 추출된 장면을 이야기 흐름의 후보 위치와 함께 표시한다 |

**사용자 흐름**: `/create` 진입 → 자유 발화 제출 → 요소 추출 및 근거/상태 저장 → 빈칸만 한 질문씩 응답 또는 모름 처리 → 질문 종료 → 다음 단계에서 로그라인 선택

## 4. API 명세

**3자 대조 대상이다** — 이 표 ↔ 서버 라우트 ↔ 클라이언트 호출이 전부 일치해야 한다.

### `POST /api/extract`

| 항목 | 값 |
|---|---|
| 요청 | `{ utterance: string }` — 비어 있지 않은 자유 발화 |
| 응답(성공) | `{ elements: Record<ElementKey, { value: string; evidence: string; confidence: number; unknown: boolean }>, questions: CreationQuestion[], maxQuestions: 10, engine: "heuristic" \| "anthropic" }` |
| 응답(실패) | 잘못된 JSON 또는 빈 발화는 `400 { error: string }`; 처리 실패는 `500 { error: string }` |
| 모델 사용 | 실키 경로에서 `MODEL_LIGHT`; 무키 경로에서는 모델을 사용하지 않는다. 실키 경로의 품질은 미검증이다(§4). |
| 무키 폴백 | 있음 — 휴리스틱 추출 후 동일한 빈칸 질문 정책을 적용한다. 데모는 이 경로로 촬영한다(§4). |
| 호출하는 곳 | `app/create/page.tsx:133-147` |

현재 라우트의 응답은 `elements`를 문자열로만 반환하고 `engine` 등 일부 메타데이터는 클라이언트 `ExtractResponseSchema`(`components/create/createSchemas.ts:30-33`)에서 계약에 포함되지 않는다. 이는 R2·R10의 갭으로 기록한다.

`confidence`의 자료형·범위·산출 방식과 `evidence`를 원문 문자열로 저장할지 문자 오프셋으로 저장할지는 PRD v3에 정의되어 있지 않으므로 확인 필요하다. 위 응답 형태는 필드 존재를 명시한 의도 계약이며, 세부 형식은 확정하지 않는다.

## 5. 데이터 모델

| 타입 | 정의 위치 | 저장 위치 | 비고 |
|---|---|---|---|
| `ElementKey` | `engine/creation.ts:8-22` | 세션의 요소 맵 | 장면·주인공·사건·주제·결말·장르·톤·시대·벤치마크·갈림길·후크 등을 식별한다 |
| `ElementEvidence` (의도 모델) | 현재 정의 없음 | `mc_session` 내부 요소 맵 | `value`, `evidence`, `confidence`, `unknown` 4종을 함께 보존해야 한다. R: 미구현 |
| `CreationQuestion` | `engine/creation.ts:28-34` | `mc_session.questions` | `id`, `elementKey`, `ask`, 선택적 `hint`, `priority` |
| `CreationSession` | `engine/creation.ts:71-82` | `localStorage["mc_session"]` | 추출 요소, 이번 세션 질문, 답변, 단계 상태를 함께 보존한다 |

**저장 키**: `mc_session`. 현재 세션은 `/create`에서 약 800ms 지연 후 localStorage에 저장된다(`app/create/page.tsx:70-83`).

**마이그레이션**: 기존 문자열 요소를 새 `ElementEvidence`로 바꾸는 규칙은 PRD에 정의되어 있지 않으며 확인 필요. 현재 코드의 저장 복원도 이전 객체를 `emptySession()`에 얕게 병합하는 수준이다(`app/create/page.tsx:45-50`).

## 6. 원칙 준수 (PRD v3 §3)

| 항목 | 이 기능에서의 의미 | 지키는 방법 |
|---|---|---|
| P1 후크는 사람 | 사용자가 말한 후크만 보존하고, 비어 있으면 AI가 후크를 만들지 않는다 | 근거구간이 없는 후크는 값으로 채우지 않고 모름/빈 상태로 둔다. 후크 확정은 4단계 입력으로 남긴다 |
| P2 정직한 표기 | 현재 결과가 휴리스틱인지 실키 모델인지 사용자가 오해하지 않아야 한다 | API와 화면의 provenance를 실제 경로와 일치시킨다. 휴리스틱 결과를 AI 생성물로 표기하지 않는다 |
| P3 되돌아갈 자유 | 질문 단계에서 앞서 말한 재료를 확인하고, 이전 단계로 돌아가도 요소와 근거를 잃지 않아야 한다 | 요소·질문·답변을 세션에 보존하고, 단계 이동은 기존 재료를 삭제하지 않는 방식으로 처리한다 |
