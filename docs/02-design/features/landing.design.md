## 0. Context Anchor

| Key | Value |
|---|---|
| **WHY** | 사용자가 제품의 차별화 축과 창작 흐름을 이해하고, 영화 탐색·새 창작·구형 대조군 중 하나로 진입하게 한다. 핵심 축은 “사용자의 말을 존중하는 계약”이다(§2). |
| **WHO** | 창작 입문자·공모전 준비생, 제품을 처음 보는 방문자, /write와 /create를 비교하는 H1 검증 참여자 |
| **RISK** | 아직 검증되지 않은 가설을 검증된 방법론이나 확정된 효과처럼 소개하면 P2를 위반하고 H1~H5의 실험을 오염시킨다. |
| **SUCCESS** | 방문자가 영화로 시작하기·내 이야기로 시작하기·기존 11필드 대조군을 구분하고, 제품 원칙·출처 상태·다음 행동을 오해 없이 이해한다. |
| **SCOPE** | 홈 탐색면, /about 소개면, /design 토큰·컴포넌트 쇼케이스, H1 대조군인 /write의 진입·보존 원칙이다. 실제 /create 생성 파이프라인 구현은 포함하지 않는다. |

## 2. 비목표 (Non-goals)

- /write를 삭제하거나 /create로 대체하지 않는다 — /write는 PRD H1의 11필드 대조군이다.
- “검증된 방법론”, “10개 질문이면 충분”, “3안이 최적”, “10분이면 완성”을 제품 사실로 확정하지 않는다 — §3-2의 가설·반박·부분 지지를 그대로 유지해야 한다.
- /about에서 AI·방법론·사용성 효과를 학술 검증 완료처럼 홍보하지 않는다 — P2는 외부 소개 문구에도 적용된다.
- /design을 실제 사용성 검증 결과나 제품 완료 상태로 취급하지 않는다 — 상태값과 예시는 디자인 시스템 쇼케이스다.
- 랜딩 기능 자체에 사용자 계정·결제·내보내기·서버 저장 API를 추가하지 않는다 — PRD §6-2와 로드맵의 후속 범위다.

## 4. API 명세

랜딩 기능이 자체 제공하는 서버 API는 **해당 없음**. 홈은 knowledge 기능의 /api/benchmark, /api/tmdb, /api/match를 소비하지만, 그 계약은 knowledge.design.md에서 정의한다. /about, /design, /write는 페이지 렌더링과 클라이언트 상태를 사용한다.

## 5. 데이터 모델

| 타입 | 정의 위치 | 저장 위치 | 비고 |
|---|---|---|---|
| 홈 라이브러리 항목 | app/page.tsx:9-11 | 서버 API 응답을 화면 상태에 보관 | origin으로 기준/AI 항목을 구분해야 한다 |
| 디자인 프리뷰 상태 | components/DesignPreview.tsx:15-90 | 페이지 로컬 상태 | 테마·시작 모드·선택 로그라인·가져오기 상태·현재 단계. 실제 작품 데이터가 아님 |
| UI 입력 상태 | components/ui/Input.tsx, Textarea.tsx | 부모 폼 상태 | label·hint·error와 aria-describedby/aria-invalid를 함께 표현 |
| 구형 입력 폼 | app/write/page.tsx:10-18 | localStorage["mc_draft"] | H1 대조군의 11필드 초안. /write를 제거하지 않는 근거와는 별개인 코드 저장 방식 |

**저장 키**: 설계상 랜딩은 방문자의 작품을 저장하지 않는다. /write의 mc_draft는 대조군 구현 데이터이며 신규 랜딩 계약으로 일반화하지 않는다.

**마이그레이션**: 랜딩 화면은 사용자 프로젝트 스키마를 소유하지 않는다. /write와 /create 사이에 입력 데이터를 자동 변환하는 요구사항은 PRD에 없다.

## 6. 원칙 준수 (PRD v3 §3)

| 항목 | 이 기능에서의 의미 | 지키는 방법 |
|---|---|---|
| P1 후크는 사람 | 소개·홈 카피가 사용자의 말을 입력 재료로 존중하고, AI가 후크를 대신 쓴다고 약속하지 않는다 | “후크는 당신”을 사용자의 기여·편집·통제라는 의미로만 설명하고, 현재 모델 성능을 근거로 삼지 않는다 |
| P2 정직한 표기 | 가설과 원칙, 기준 작품과 AI 초안, 휴리스틱과 실키를 섞지 않는다 | /about은 검증 전 가설을 확정 문구로 쓰지 않고, 24+76은 “거장 확정/AI 분석 초안”으로 표시한다 |
| P3 되돌아갈 자유 | 방문자는 영화 탐색·새 창작·11필드 대조군 사이를 선택하고 돌아갈 수 있다 | /write 링크를 유지하고, 이전 단계·다음 행동·아직 비어 있음 상태를 잠그지 않는 UI 규칙으로 표현한다 |

H1~H6과의 관계: 랜딩은 가설을 주장하는 곳이 아니라 실험 조건을 안내하는 표면이다. 특히 /write를 제거하지 않아 H1의 11필드 대 /create 무작위 비교를 보존한다. H-A/H-B/H-C/H-E/H-F는 소개 문구에서 검증된 사실로 승격하지 않는다.
