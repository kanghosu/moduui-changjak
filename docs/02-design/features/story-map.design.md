| 항목 | 값 |
|---|---|

| 작성 | W2 / 2026-08-30 |
| 근거 문서 | `docs/PRD_v3.md` §3, §4, §6, §8, §9, §11, §12 |

> 24블록·4막은 검증된 방법론이라는 뜻이 아니다. PRD v3 §3-2의 H-F(부분 지지, 24블록 자체 미검증)에 따라 이 문서는 이를 검증할 가설을 구현하는 의도로 기록한다.

## 0. Context Anchor

| Key | Value |
|---|---|
| **WHY** | 자유 발화와 선택 결과를 완성 가능한 이야기 구조로 볼 수 있게 한다. PRD v3 §1·§4의 5단계 중 5단계인 이야기 지도다. |
| **WHO** | 창작 입문자와 공모전 준비생. 구조를 직접 확정하고 싶은 사용자다. |
| **RISK** | 24블록을 검증된 정답으로 오인하거나, AI 분석 초안을 확정 자료로 오인하면 소유감과 정직한 표기가 무너진다. |
| **SUCCESS** | 로그라인을 선택한 사용자가 4막으로 묶인 24칸 지도를 확인하고, 장면 후보에는 근거와 `AI 분석 초안 기준` 표기가 붙으며, 외부 문서에서는 24블록을 검증 완료 방법론으로 부르지 않는다. |
| **SCOPE** | `/create`의 이야기 지도 생성·표시와 장면→후보 블록 역산이다. 원문 추출, 로그라인 생성, 작업실 편집·스냅샷은 이 문서의 주 책임이 아니다. |

## 1. 기능 요구사항

| ID | 요구사항 | PRD 근거 | 우선순위 |
|---|---|---|---|
| R1 | 사용자가 이야기 뼈대(로그라인)와 앞 단계의 창작 입력을 확정하면 4막에 배치된 24블록 이야기 지도를 출력한다 | §4 5단계, §3-2 H-F | P0 |
| R2 | 이야기 지도 결과가 있으면 24개의 진행 칸을 가로 타임라인으로 같은 폭으로 표시한다 | §4 5단계 | P0 |
| R3 | 사용자가 인상적인 장면을 입력하면 그 장면이 들어갈 수 있는 이야기 흐름의 후보 블록과 후보를 고른 이유를 출력한다 | §4 2단계 | P1 |
| R4 | 장면 후보와 참고 작품의 근거가 AI 분석 초안이면 결과 영역에 `AI 분석 초안 기준`이라고 표시한다 | §3-1 P2, §4 대외 표기 규칙, §6-1 | P0 |
| R5 | 사용자가 후크를 입력하면 이야기 지도 생성 시 그 후크를 창작자 입력으로 보존하고 AI가 후크를 대신 확정하지 않는다 | §3-1 P1, §4 4단계 | P0 |
| R6 | 24블록·4막 지도를 제공하되 이를 검증된 방법론 또는 검증 완료 결과로 표기하지 않고 H-F 검증 대상으로 취급한다 | §3-2 H-F, §8 H4 | P0 |
| R7 | 모델 키가 없는 실행 환경에서도 데모에 필요한 지도·장면 배치 흐름을 mock/휴리스틱 경로로 제공한다 | §4, §11 데모 범위 | P1 |
| R8 | 사용자가 지도에서 이전 창작 단계로 돌아가도 이미 만든 하위 산출물을 지우지 않고 다시 검토할 수 있다 | §3-1 P3, §9 | P1 |

## 2. 비목표 (Non-goals)

- 24블록·4막을 학술적으로 검증된 정답이나 유일한 구조로 판정하지 않는다 — 이유: PRD §3-2 H-F에서 24블록 자체가 미검증이다.
- AI 분석 초안 76편을 거장 확정 24편으로 표시하지 않는다 — 이유: PRD §3-1 P2와 §6-1의 서비스 런타임 층 구분 때문이다.
- 장면 원문을 새로 쓰거나 사용자의 결말·후크를 자동 확정하지 않는다 — 이유: 사용자 말을 존중하는 제품 축과 P1 때문이다.
- 스토리툰 생성, 결제, 스트리밍, i18n, 계정·서버 저장은 이 기능의 완료 조건이 아니다 — 이유: §4와 §11에서 아직 없는 것 또는 후속 단계로 명시했다.
- 24블록 구조가 빈 캔버스보다 낫다고 결론내리지 않는다 — 이유: H-F는 §8 H4에서 완성률·인과 연결·소유감으로 검증해야 한다.

## 4. API 명세

### `POST /api/generate`

| 항목 | 값 |
|---|---|
| 요청 | `{ logline: string, premise?: string, genre?: string, target?: string, tone?: string, hookNote?: string, benchmarkName?: string, theme?: string, heroName?: string, heroWant?: string, heroNeed?: string, ideaNote?: string }` |
| 응답(성공) | `{ story: Story }` — 4막에 속한 24개 블록을 포함하는 이야기 지도 |
| 응답(실패) | HTTP 400/500과 오류 메시지. 구체적 오류 코드·메시지 형식은 PRD에 정의되지 않아 확인 필요 |
| 모델 사용 | 실제 모델 경로와 모델명은 PRD에서 확정하지 않는다. 데모는 mock 경로를 사용한다 |
| 무키 폴백 | 있음 — 모델 키가 없으면 mock 경로로 지도 결과를 반환한다 |
| 호출하는 곳 | `app/create/page.tsx:186-199` (현재 클라이언트는 `pipeline: true`도 전송하나 이는 별도 미기재 동작이다) |

### `POST /api/scene-blocks`

| 항목 | 값 |
|---|---|
| 요청 | `{ sceneText: string }` |
| 응답(성공) | `{ candidates: [{ index: number, act: 1|2|3|4, function: string, reason: string }], benchmarks: [{ title: string, year: string, genre: string, reason: string, matchedBlocks: number[] }] }` |
| 응답(실패) | HTTP 400/500과 오류 메시지 |
| 모델 사용 | 실제 모델 경로와 성능 보증은 PRD에서 확정하지 않는다 |
| 무키 폴백 | 있음 — 휴리스틱 후보와 AI 분석 초안 라이브러리 기반 참고 작품을 반환한다 |
| 호출하는 곳 | `components/ScenePlacement.tsx:68-73`; 화면 연결은 `components/create/QuestionStage.tsx:92` |

## 5. 데이터 모델

| 타입 | 정의 위치 | 저장 위치 | 비고 |
|---|---|---|---|
| `Block` | `engine/schema.ts:21-40` | 프로젝트 데이터의 블록 배열 | 24블록 지도에서 한 칸을 표현한다 |
| `Story` | `engine/schema.ts:42-63` | 프로젝트 데이터 | 로그라인·인물·블록·노트를 함께 가진다 |
| `CreationSession` | `engine/creation.ts:68-82` | 브라우저 세션 저장 | 단계 이동 시 하위 산출물을 유지하는 세션 모델이다 |

**저장 키**: PRD는 프로젝트·세션·스냅샷이라는 사용자 데이터 층만 정의하며 구체 키는 정의하지 않는다. 현재 구현 키(`mc_session`, `mc_project`, `mc_works`)와 저장 동기화 규칙은 `studio` 문서 및 별도 갭 보고서에서 다룬다.

**마이그레이션**: PRD v3에는 지도·세션의 구형 스키마 흡수 규칙이 없다. 구형 데이터가 있을 경우의 정책은 확인 필요다.

## 6. 원칙 준수 (PRD v3 §3)

| 항목 | 이 기능에서의 의미 | 지키는 방법 |
|---|---|---|
| P1 후크는 사람 | 지도는 구조를 보조하지만 창작자의 차별화 입력을 대체하지 않는다 | `hookNote`를 입력·보존하고, 지도 생성 결과가 후크의 소유자를 AI로 바꾸지 않게 한다 |
| P2 정직한 표기 | 후보의 출처와 24블록의 검증 상태를 과장하지 않는다 | 장면 배치 영역에 `AI 분석 초안 기준`을 표시하고, 24블록을 H-F 가설로 설명한다 |
| P3 되돌아갈 자유 | 지도를 본 뒤 이전 단계의 발화·선택·후크로 돌아갈 수 있어야 한다 | 단계 이동 시 하위 산출물을 삭제하지 않고 현재 지도와 세션을 함께 보존한다 |
| H-F 구조 가설 | 4막·24블록은 사용자에게 제공할 실험 조건이다 | §8 H4의 빈 캔버스·구조 선택형 비교와 완성률·인과 연결·소유감 측정을 별도로 진행한다 |

## 7. 검증 기준

| 검증 | 방법 | 통과 조건 |
|---|---|---|
| 구조 단위 | `Story`가 24개 블록과 4개 막을 표현하는지 확인 | 24칸이 누락·중복 없이 표시됨 |
| 출처 표기 | 장면 텍스트 입력 후 후보 영역 확인 | `AI 분석 초안 기준`이 보이고 거장 확정 자료로 오인할 문구가 없음 |
| 무키 경로 | 키 없는 환경에서 `/create` 1~5단계 실행 | 지도와 장면 후보 흐름이 중단되지 않음 |
| 타입 | `npx tsc --noEmit` | 에러 0 |
| 빌드 | `npx next build` | 성공 |
| H-F 실험 | PRD §8 H4의 빈 캔버스 / 4막·24블록 / 구조 선택형 비교 | 완성률뿐 아니라 인과 연결 독립평가와 소유감까지 기록하고, 수치가 없으면 `없음`으로 둠 |
| 실사용 | 오케스트레이터가 브라우저에서 직접 확인 | 장면 입력→후보·근거·출처 표기, 로그라인 선택→24칸 지도, 이전 단계 복귀를 확인 |
