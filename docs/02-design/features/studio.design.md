## 0. Context Anchor

| Key | Value |
|---|---|
| **WHY** | 완성된 이야기 지도를 사용자가 자기 문장과 사건으로 계속 다듬고, 실험하더라도 이전 버전으로 돌아가게 한다. |
| **WHO** | 이야기 지도를 만든 창작 입문자·공모전 준비생과 여러 작품을 이어서 작업하는 사용자다. |
| **RISK** | 편집 내용·스냅샷·서재 작품이 서로 다른 저장 상태가 되면 사용자가 작업을 잃고 P3의 통제감을 잃는다. |
| **SUCCESS** | 사용자가 서재의 여러 작품 중 하나를 작업실에서 열고, 블록을 수정·확정하고, 실험 전 스냅샷을 만든 뒤 그 버전으로 복원할 수 있으며, 새 작품을 만들어도 기존 작품이 남는다. |
| **SCOPE** | `/studio` 블록 편집, 원문·제안의 사용자 선택, 스냅샷·복원, `/library`와 프로젝트 재방문 연결, PRD가 우선순위로 둔 프로젝트 내보내기·가져오기다. |

## 1. 기능 요구사항

| ID | 요구사항 | PRD 근거 | 우선순위 |
|---|---|---|---|
| R1 | 이야기 지도가 있으면 작업실에서 4막 레인과 24개 블록을 보여주고 사용자가 블록을 선택해 자기 사건을 편집한다 | §4 5단계, §9 | P0 |
| R2 | 사용자가 블록의 사건을 수정하고 저장하면 수정한 문장을 현재 프로젝트에 보존한다 | §3-1 P1, §3-1 P3, §9 내 손을 거친 흔적 | P0 |
| R3 | 사용자가 다른 전개를 시도하기 전에 스냅샷을 요청하면 현재 이야기 버전을 별도 버전으로 보존한다 | §3-1 P3, §9 잃지 않는다 | P0 |
| R4 | 사용자가 저장된 스냅샷을 선택하면 그 시점의 이야기로 복원하고 작업을 이어갈 수 있다 | §3-1 P3, §9 | P0 |
| R5 | 사용자가 새 이야기를 저장해도 기존 서재 작품을 덮어쓰지 않고 여러 작품을 다시 열 수 있다 | §6-1 B층, §9 작업이 쌓인다·프로젝트 재방문 | P0 |
| R6 | 서재에서 작품을 열고 작업실로 이동하면 선택한 작품의 현재 작업을 편집 대상으로 사용한다 | §6-2, §9 | P1 |
| R7 | AI 제안이 제공되더라도 사용자가 가져오기·편집을 선택하며 사용자가 쓴 원문을 자동 삭제하지 않는다 | §3-1 P1, §3-1 P3 | P1 |
| R8 | 사용자가 프로젝트를 JSON으로 내보내고 Markdown으로도 내려받으며, JSON을 다시 가져와 프로젝트를 복구할 수 있다 | §6-2 순서 1, §11 데모 목표 | P0 |
| R9 | 계정·서버 없이 데모를 실행하면 브라우저 저장으로 작업을 보존하고, 이후 Dexie·계정·서버 저장으로 확장할 수 있는 저장 경계를 유지한다 | §4 아직 없는 것, §6-2 순서 2~3 | P1 |

## 2. 비목표 (Non-goals)

- 클라우드 계정·서버 저장을 현재 데모의 전제 조건으로 삼지 않는다 — 이유: PRD §4와 §6-2에서 내보내기를 먼저 두고 계정·서버를 후속 단계로 둔다.
- 구글 Drive를 주 저장소로 사용하지 않는다 — 이유: §6-3에서 단독 저장을 기각했다.
- 스냅샷을 사용자의 동의 없이 자동 삭제하지 않는다 — 이유: P3의 되돌아갈 자유와 §9의 “잃지 않는다” 때문이다.
- 스토리툰 생성·결제·커뮤니티·i18n은 작업실 편집 완료 조건에 포함하지 않는다 — 이유: §4·§11에서 아직 없거나 P3로 미뤄졌다.
- 24블록 구조 자체의 효과를 작업실 사용만으로 검증 완료했다고 결론내리지 않는다 — 이유: H-F는 별도 비교 실험 대상이다.

## 3. 화면·컴포넌트

| 화면/컴포넌트 | 파일 | 책임 |

| 저장소 타입·어댑터 | `engine/library.ts` | 작품 컬렉션, 현재 편집 프로젝트, 구형 단일 슬롯 흡수를 정의한다 |
| 지도 생성 후 저장 연결 | `app/create/page.tsx` | 생성된 Story를 서재·작업실의 다음 작업 대상으로 넘긴다 |

**사용자 흐름**: 이야기 지도 생성 → 서재에 저장 → `/library`에서 작품 선택 → `/studio`에서 블록 수정·확정 → 실험 전 스냅샷 → 필요할 때 복원 → 계속 편집

## 4. API 명세

### 스냅샷·복원·블록 저장

| 항목 | 값 |
|---|---|
| 요청 | 해당 없음 — 현재 의도는 브라우저 저장소 기반이다 |
| 응답(성공) | 해당 없음 — 현재 프로젝트·스냅샷 상태가 저장소에 보존된다 |
| 응답(실패) | 저장 공간 부족 또는 복구 실패를 사용자에게 알린다. 구체 상태코드는 확인 필요 |
| 모델 사용 | 스냅샷·복원 자체는 사용하지 않음 |
| 무키 폴백 | 해당 없음 |
| 호출하는 곳 | API 호출 없음. 관련 저장 호출은 `app/studio/page.tsx:103-124`, `app/library/page.tsx:63-70` |

### 작업실 보조 API

작업실이 참고 작품·제안 API를 호출하는 현재 동작은 PRD v3에 요청·응답 계약이 정의되어 있지 않으므로 이 설계문서의 기능 계약으로 확정하지 않는다. 코드에만 있는 호출과 판단은 `docs/02-design/_unbacked/studio.md`에 기록한다.

## 5. 데이터 모델

| 타입 | 정의 위치 | 저장 위치 | 비고 |
|---|---|---|---|
| `Work` | `engine/library.ts:15-25` | 사용자 작품 컬렉션 | 여러 작품이 쌓이고 다시 열리는 단위다 |
| `CurrentProject` | `engine/library.ts:27-36` | 현재 작업 프로젝트 슬롯 | Story·확정 상태·스냅샷·초안 원본·작품 연결 정보를 가진다 |
| `Story` / `Block` | `engine/schema.ts:21-63` | `Work`·`CurrentProject` 내부 | 이야기 지도와 블록 편집 대상이다 |
| 스냅샷 | `CurrentProject.snapshots` | 현재 프로젝트의 버전 목록 | 각 버전은 시각과 Story를 보존한다 |

**저장 키**: PRD는 키 이름을 정하지 않는다. 현재 구현은 작품 컬렉션 `mc_works`와 작업실 현재 슬롯 `mc_project`를 사용한다. 이 두 표현의 동기화는 제품 요구사항의 내부 구현이 아니라 P3·§9를 만족해야 하는 일관성 조건이다.

**마이그레이션**: 구형 단일 슬롯을 여러 작품 서재로 흡수하는 정책과 중복 판정은 PRD에 정의되지 않았다. 실제 정책은 별도 갭 보고서에서 확인 필요로 남긴다.

## 6. 원칙 준수 (PRD v3 §3)

| 항목 | 이 기능에서의 의미 | 지키는 방법 |
|---|---|---|
| P1 후크는 사람 | 작업실은 사용자의 사건·문장을 중심 산출물로 취급한다 | AI 제안은 선택 가능한 보조물로 두고, 원문과 사용자의 편집을 보존한다 |
| P2 정직한 표기 | 참고작·제안·스냅샷의 출처와 현재 상태를 혼동시키지 않는다 | AI 분석 초안과 거장 확정 자료를 구분하고, 확인되지 않은 모델 성능을 주장하지 않는다 |
| P3 되돌아갈 자유 | 실험·편집·단계 이동 후에도 이전 결과를 되찾는다 | 스냅샷을 만들고 복원하며, 서재 전환이나 새 작품 생성이 기존 버전·작품을 제거하지 않게 한다 |

## 7. 검증 기준

| 검증 | 방법 | 통과 조건 |
|---|---|---|
| 저장 로직 | `tests/library.test.ts` | 여러 작품 저장, 동일 작품 갱신, 손상값 방어, 구형 슬롯 흡수 테스트 통과 |
| 편집 보존 | 작업실에서 블록 문장 수정→저장→새로고침 | 수정 문장과 사용자 원문이 의도대로 보존됨 |
| 스냅샷 | 스냅샷 생성→블록 수정→복원 | 스냅샷 시점 Story로 돌아가며 현재 작업을 계속할 수 있음 |
| 작품 전환 | 작품 A 스냅샷→작품 B 열기→A 재열기 | A의 편집·확정·스냅샷이 B 전환으로 사라지지 않음 |
| 탈출구 | JSON+Markdown 내보내기→JSON 가져오기 | 계정 없이 프로젝트를 복구하고 원래 이야기·블록을 확인할 수 있음 |
| 타입 | `npx tsc --noEmit` | 에러 0 |
| 빌드 | `npx next build` | 성공 |
| 실사용 | 오케스트레이터가 브라우저에서 직접 | 서재 여러 작품, 작업실 편집, 실험 전 스냅샷, 복원, 재방문을 확인 |
