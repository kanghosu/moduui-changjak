| 위치 | `app/create/page.tsx`의 `runExtract()` — `patch({ elements: toExtractedElements(fresh), answers: {}, ... })` |
| 원인 | `answers`를 `{}`로 비우고 `elements`를 새 추출로 **통째 교체**한다. 이전 `unknown` 표시가 사라진다 |
| 위반 | PRD v3 **§2**(유일한 차별화 축), **H-B** |
| 심각도 | **P0** — 제품이 하지 않겠다고 약속한 바로 그 동작이다 |

**실브라우저 재현(2026-08-31)**
```
1. scene = { value:"", confidence:"high", unknown:true }  (사용자가 "없음"이라 답한 상태)
2. "더 떠들기"로 1단계 복귀 → "이야기 정리 시작" 재실행
3. 재추출 후 scene 요소가 사라짐. 질문 9개 재생성
   → 화면에 "머릿속에 가장 강렬하게 남아 있는 장면이 있나요?" 다시 표시

   판정: FAIL — 사용자가 "없음"이라 답한 것을 다시 묻는다
```

**확인된 사실**: `onSkipQuestion`은 `nextQuestion("없음")`을 호출하므로, 명시적 건너뛰기는
`answers[qid] === "없음"`으로 기록되고 **아직 안 본 질문(`undefined`)과 구분된다.** 수정에 이 구분을 쓴다.

**조치**: Wave 5. `ExtractedElement`에 `source: "user" | "extracted"`를 추가해
사용자가 말한 것(답변·수동 편집·명시적 없음)을 새 추출이 덮지 못하게 한다.

## 13. 🔴 검증 중 드러난 사실 — 휴리스틱 추출의 실제 성능

Wave 5 정상 경로 검증에서 나온 실측이다. **결함 수정이 아니라 현재 상태의 기록이다.**

입력한 발화:
> "주인공은 평범한 회사원이다. 옥상에서 회사의 비리 장부를 발견하고 손이 떨린다.
> 결국 모든 것을 잃고 진실을 택한다."

이 한 문단에 **주인공·장면·결말**이 전부 들어 있다. 그런데 결과는:

| 항목 | 값 |
|---|---|
| 추출된 요소 | **`heroDesc` 1개뿐** (`extracted` / `low`) |
| 생성된 질문 | **9개** |
| 놓친 것 | 장면(옥상 비리 장부) · 결말(모든 것을 잃고 진실을 택한다) |

**이것이 9/5 데모에서 보일 화면이다.** PRD v3 §4·§11이 데모를 mock/휴리스틱 경로로
촬영하기로 정했으므로, **"이미 말한 건 다시 묻지 않는다"는 약속이 데모에서 가장 약하게 보인다.**

- G7·G14는 **구조**를 고쳤다. 말한 것을 기록하고 다시 묻지 않는 계약은 이제 코드에 있다.
- 남은 것은 **추출 자체의 성능**이다. 이건 코드 구조가 아니라 ① 실키(Anthropic) 경로 또는
  ② 휴리스틱 규칙 보강으로만 올라간다.
- **해소 조건**: `ANTHROPIC_API_KEY`. 확보되면 실키 경로에서 같은 발화로 추출 요소 수와
  질문 수를 재측정해야 한다. 그 전까지 데모에서 이 축을 강조하지 않는 편이 안전하다(P2).

`repeatQuestionRate()`는 이제 이 값을 지표로 잴 수 있게 해준다(PRD §5).
