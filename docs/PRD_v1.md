# PRD v1 — 모두의 창작 「모두의 영화」
2026-08-24 · 작성: 기획(Fable) · 승인 대기: 김태원 대표 / 강호수 CTO
근거: 창업팀 회의록(자유발화 플로우 결정), OKF 지식베이스(개념 344·책 256p·강의 533장), 기존 MVP(작법 엔진 + 영화 라이브러리 76편)

## 1. 비전과 목표
**한 줄**: 신인 창작자가 "내 글"이라는 소유감을 잃지 않으면서, 거장의 방법론(욕망의 레시피 4막·24블록)으로 영화급 스토리를 완성하는 창작 툴.

| # | 목표 | 측정 |
|---|---|---|
| G1 | '모두의 스토리' 성공 사례 창출 — 툴로 완성된 잘 쓴 글이 곧 마케팅 | 완주작 수, 완주율 |
| G2 | 글로벌 타깃 | i18n 준비(en 우선), 해외 이론 호환(Dramatica 등 크로스워크) |
| G3 | 커뮤니티 + 웹툰화 + 거래 기반 | 열람·공유·판매 파이프라인 |

## 2. 문제 정의 (우리가 이기는 지점)
기존 AI 창작: 프롬프트 한 번에 완성문을 "딸깍" 생성 → 사용자는 자기 글로 느끼지 못하고 이탈. **글은 서너 번 이상 자기 손을 거쳐야 자기 글이 된다.**
→ 우리는 이탈률을 감수하더라도 **플로우를 잘게 쪼개 매 단계 사용자의 선택·입력·브레인스토밍이 개입**하는 UX로 소유감을 만든다. (회의 결정: "정리→분석→확장→선택→배치", 질문 총량 ≤10, 24블록 용어는 최종 단계까지 은닉)

## 3. 타깃
- 1차: 신인 창작자(습작생·공모 준비생·웹소설/시나리오 지망) — 구조 지식 없음, 소재/장면만 있음
- 2차: 강의 수강생(욕망의 레시피 커리큘럼 연동), 3차: 글로벌 아마추어(영어 UI)

## 4. 핵심 플로우 — 두 가지 입력 모드 (회의 결정)
**모드 A · 장면 우선(Scene-first)**: "떠오른 인상적인 장면"을 먼저 쏟아냄(텍스트/음성) → AI가 그 장면이 들어갈 수 있는 블록 후보 3~4개를 역산 제시 → 빈 곳(앞뒤 인과)을 단계별로 채움. *근거: 인상 장면은 24블록 중 3~4개 블록에만 배치 가능(회의)*
**모드 B · 문답 우선(Guided Q&A)**: 짧은 설문+대화로 방향 잡기 — 단 빈칸 채우기 금지. 먼저 자유 발화 → 부족한 항목만 질문(풀 10개 상한) → 로그라인 3안+벤치마크 영화 제시 → 선택 → 심화.
공통 원칙: ① 어느 단계든 뒤로 자유 이동 ② 우측 진행 내비게이터 상시 ③ "플롯이 뭐예요?" 같은 탈선 질문을 받아주는 도움말(F1) — 답은 knowledge/위키에서 ④ 24블록·전문용어는 최종 산출 단계에서만 노출.

## 6. 경쟁·벤치마크
- **Dramatica Pro**: 이론 정합성 최고·학습장벽 최악(질문 수십 개) → 우리는 "질문 ≤10 + 자유 발화"로 역포지셔닝. 단 Storyform식 일관성 검사 아이디어는 검증기에 흡수.
- **스토리헬퍼(이대 엔터/한콘진)**: 설문 30문항+205편 DB — 질문 중복·피로가 실패 요인(회의 실사용 증언). 영화 DB 매칭 아이디어만 계승.
- **Save the Cat! 소프트웨어/Plottr**: 보드형 구조 시각화 — 24블록 타임라인 UI 참고.
- **Sudowrite/NovelAI**: "딸깍" 생성의 대표 — 소유감 부재가 우리 차별점.

## 7. 기능 로드맵
**P1 소유감 창작 코어 (지금)**
- F1 두 입력 모드(A 장면 우선 / B 문답) + 음성 입력
- F2 부족항목 질문 엔진(풀 10, 위키 근거) · F3 로그라인 3안+벤치마크 · F4 단계별 심화(캐릭터/장르 이벤트/플롯포인트/취재)
- F5 24블록 최종 산출 + 구조 검증기(반전점13·악마 9-14-18·B스토리 8-15-22) + 보정 제안
- F6 F1 도움말(개념 344 기반 "플롯이 뭐예요?")
**P2 시각화·수익화**: 스토리툰(웹툰형 시각화, 결제 지점 — 회의: 여기서 첫 과금) · 데모/무빙툰 export · 가격은 무료 오픈 후 DAU 100 데이터로 결정(구독 <3만원 vs 토큰 충전 — 미결)
**P3 커뮤니티·거래**: 완성작 갤러리(락인) · 열람/공유 → 판매(IP 거래 스텁) · 숏폼 노출 채널
**P4 글로벌**: en UI · 해외 이론 용어 크로스워크 노출 · 글로벌 벤치마크 영화 확대

## 8. 아키텍처 (기존 MVP 위 증분)
- Next.js App Router 유지. `engine/`에 **knowledge-pack 로더** 추가: concept_registry.json(발췌) + 24block.md를 프롬프트 컨텍스트/검증 규칙으로 주입
- 모델 라우팅(토큰 최적화): 추출·분류=Haiku, 로그라인·심화 대화=Sonnet, 최종 24블록 설계·검증=Sonnet(필요시 Opus), 서버측 캐시
- 장면 역산 API: 장면 텍스트 → 후보 블록 3~4 + 유사 벤치마크 장면
- 데이터: 프로젝트 저장(로컬→DB), 이벤트 로그(단계 이탈 측정)

## 9. 성공 지표 (P1)
완주율(시작→24블록 산출) ≥ 25% · 단계 이탈 상위 지점 파악 가능 · 로그라인 3안 중 선택률 ≥ 70%(재생성 아닌 선택) · "내 글 같다" 정성 피드백 · F1 도움말 사용률
