# PRD v2 — 모두의 창작

2026-08-25 · 개정: 오케스트레이터(Claude Opus) · 승인 대기: 김태원 / 강호수
전신: `docs/PRD_v1.md`(2026-08-24). v1의 방향은 유지하고, **실제로 만들어진 것과 실사용 검증에서 드러난 사실**로 갱신한다.

## 0. v1에서 무엇이 바뀌었나

| 항목 | v1 | v2 (근거) |
|---|---|---|
| 입력 모드 | 모드 A(장면 우선) / 모드 B(문답 우선) **분기** | **단일 플로우로 통합.** 장면 역산은 분기가 아니라 2단계 안의 기능으로 붙었다. 사용자에게 모드를 고르게 하는 것 자체가 첫 질문이 되어 "질문 없이 시작" 원칙과 충돌한다 |

| 핵심 리스크 | 미식별 | **추출 품질이 제품의 생명선**임이 실사용에서 확인됨 (§4) |
| 데이터 전략 | 미정 | 서비스 데이터와 지식 자산을 분리 (§6) |

## 1. 한 줄 정의

**떠들면 이야기가 된다** — 신인 창작자가 "내 글"이라는 소유감을 잃지 않으면서, 검증된 방법론(욕망의 레시피 4막·24블록)으로 완성 가능한 이야기 구조를 얻는 도구.

## 2. 지금 실제로 작동하는 것 (2026-08-25 실행 검증 완료)

`/create` 5단계. 무키 상태에서도 전 구간이 돈다.

| 단계 | 화면 이름 | 작동 내용 | 근거 |
|---|---|---|---|
| 1 | 쏟아내기 | 자유 텍스트 + 음성(Web Speech API). 질문 없음. 선택적 가이드 칩 5개 | `app/create`, `components/VoiceInput.tsx` |
| 2 | 뼈대 찾기 | 발화→요소 추출 → **비어 있는 것만** Typeform식 한 화면 한 질문(≤10, "약 N개 남음") + **장면→후보 블록 역산**("AI 분석 초안 기준" 라벨) | `/api/extract`, `/api/scene-blocks` |
| 3 | 이야기 고르기 | 로그라인 3안(정공법/관계/아이러니) + 벤치마크 영화·근거 | `/api/loglines` |
| 4 | 깊게 만들기 | 인물·사건·흐름·취재 축 심화 + **후크(AI가 채우지 않는 칸)** | `/create` |
| 5 | 이야기 지도 | Plottr식 가로 타임라인. 4막·인물선·앵커 칩(반전점13, 적대자9·14·18, B스토리8·15·22) → 스토리툰 CTA(준비 중) | `/api/generate`, `StoryTimeline` |

**아직 없는 것**: 계정·서버 저장(현재 localStorage), 스토리툰 실제 생성, 결제, 커뮤니티, 스트리밍 응답, i18n.

## 3. 설계 원칙 (양보 불가)

1. **질문을 먼저 주지 않는다.** 총 질문 10개 상한은 코드로 강제한다(`MAX_QUESTIONS`).
2. **이미 말한 것은 다시 묻지 않는다.** 이것이 깨지면 제품의 존재 이유가 사라진다 — 회귀 테스트 대상(§4).
3. **24블록·전문 용어는 5단계 전까지 노출하지 않는다.** 내비게이터도 순화된 이름을 쓴다.
4. **후크는 사람.** 차별화 지점은 반드시 사용자 입력에서 나온다.
5. **정직한 표기.** 생성물의 근거가 AI 분석 초안이면 그렇게 쓴다. "검증 완료"로 부풀리지 않는다.
6. **되돌아갈 자유.** 어느 단계로든 이동 가능하고, 하위 산출물은 지우지 않는다.

## 4. 최대 리스크 — 추출 품질

2026-08-25 실사용 검증에서 **"주인공은 평범한 회사원"이라고 말했는데도 주인공을 다시 묻는** 사례가 나왔다. 원칙 2가 깨진 것이고, 이 제품에서는 치명적이다.

- 원인: 무키 폴백 추출기가 장르·톤만 잡고 있었다. 장면도 첫 문장만 잘라 `/api/scene-blocks`에 빈약한 입력이 갔다.
- 조치(완료): 주인공·사건·주제·결말·시대 패턴 추가, 장면은 문장 통째로 보존, 벤치마크 매칭 불용어 보강.
- 결과: 질문 8→6개, 장면 배치 근거가 '하나·손에' → '옥상·비리'로 바뀜.
- **남은 일**: 실키(Haiku) 경로 검증. 데모 촬영 전 필수.

**회귀 테스트를 코드로 고정한다**(신규): 대표 발화 N개에 대해 "말한 요소는 질문 목록에 없어야 한다"를 자동 검사.

## 5. 빠른 검증 계획 (데모 전)

가설을 문장으로 고정하고, 반증 가능한 지표만 본다.

| # | 가설 | 측정 | 반증 기준 |
|---|---|---|---|
| H1 | 자유 발화가 항목 입력보다 시작 장벽이 낮다 | 동일 과제로 기존 `/write`(11필드) vs `/create` 비교, 최소 3명 | 첫 산출물까지 시간이 더 걸리면 기각 |
| H2 | 질문 10개 이하면 피로하지 않다 | 실제 질문 수, 중도 이탈 지점 | 5개 이전에 이탈이 몰리면 기각 |
| H3 | 로그라인 3안 중 하나는 "내 이야기 같다" | 선택률, 선택 후 수정량 | 3안 모두 거부가 절반 이상이면 기각 |
| H4 | 이야기 지도를 보면 스토리툰을 원한다 | CTA 클릭률, 가격 제시 후 결제 의향 | 관심 표명이 거의 없으면 수익모델 재검토 |

대상: 창작 입문자·공모전 준비생. 인터뷰 10명, 사용성 테스트 5명. **결과는 실제 수치만 기록하고, 없으면 "없음"으로 둔다.**

## 6. 데이터 전략 — 세 층으로 분리 (신규)

실측(2026-08-25) 결과 층마다 성격이 완전히 다르다. 한 덩어리로 "클라우드에 올린다"고 다루면 안 된다.

| 층 | 내용 | 크기 | 어디에 | 왜 |
|---|---|---|---|---|
| **A. 서비스 런타임** | 영화 라이브러리 24+76편, 방법론 문서, 개념팩 | **2.6MB** | **리포에 그대로** | 작고 버전 관리가 이득. DB로 옮길 이유가 없다 |
| **B. 사용자 데이터** | 계정, 프로젝트, 세션, 스냅샷 | 사용량 비례 | **클라우드 DB 필요** | 현재 localStorage — 브라우저 바꾸면 소멸. 다중 프로젝트·공유·지표 측정 전부 막힘 |
| **C. 지식 원본·중간산출** | 패킷 결과 612MB, OKF wiki 24MB, 슬라이드 렌더 16GB, 원본 84GB | 대용량 | **오브젝트 스토리지 백업** (서비스는 미참조) | 16GB는 대부분 PNG로 서비스와 무관. 팀 백업·검수용 |

**따라서 "DB 클라우드"의 실체는 B다.** C는 백업이지 제품 기능이 아니다.
→ B 후보: Supabase(Postgres+Auth+RLS, 무료 티어로 시작 가능). 보안은 과거 침해 이력을 감안해 RLS·시크릿 관리를 처음부터 건다.
→ **결정 필요**: 프로바이더, 그리고 C를 어디에 백업할지(현재 OneDrive 원본 존재).

## 7. 수익모델 (v1 유지, 근거 보강)

무료(정리·로그라인) → 저가 구독(심화·다중 프로젝트) → **스토리툰 변환 건별 정찰제**.
가격은 확정하지 않는다. 이미지 생성 원가·재생성률·결제 의향을 측정한 뒤 정한다(회의: 무료 오픈 후 DAU 100 데이터로 3인 재결정).
