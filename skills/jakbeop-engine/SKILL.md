# Skill: 작법 엔진 (욕망의 레시피 / 4막·24블록)

## 목적
아이디어/로그라인을 입력받아, 김태원 「욕망의 레시피」의 판단 규칙에 따라
**4막·24블록 원천스토리 설계도**를 생성한다.
이 스킬은 '일반 작법 지시'가 아니라 거장의 구조적 판단을 인코딩한다.

## 핵심 원칙
- **플롯은 AI, 후크는 인간**: 구조·인과·배치는 엔진이 설계하되, 차별화 후크/감정 디테일은
  사용자 입력(`hookNote`)을 최우선으로 반영하고, 결정 지점은 사용자에게 남긴다.
- **구조 무결성 > 화려함**: 반전·욕망선·인과가 끊기면 실패다.

## 입력 계약 (Input)
```json
{ "logline": "...", "premise": "...", "genre": "...", "target": "...", "tone": "...", "hookNote": "(선택) 창작자가 강조할 차별화 포인트" }
```

## 처리 흐름 (R1 → R6)
> 각 R은 `.claude/agents/`의 서브에이전트로 위임 가능. 방법론 세부는 `knowledge/method/*`를 **근거로 인용**한다.

- **R1 취재/정합성** — 소재·설정이 신뢰도 위계(설문<행동<재참여<금전적 약속)에 비춰 타당한지 점검. → `knowledge/method/R1_*.md` *(원본 규칙으로 채움)*
- **R2 구조 설계** — 4막·24블록 배치. 막 경계, **중심 반전점**(즉각적 욕망 → 반성적 욕망 전환), **적대자 상승(블록 9·14·18)**, **B스토리 동맹선(블록 8·15·22)**. 블록별 기능은 `knowledge/method/24block.md` 기준. *(블록 기능 정의: 원본으로 채움)*
- **R3 인물·욕망선** — 주인공 감정 곡선 + **욕망 4축(요구/이야기/욕망/결핍)** 매핑. → `knowledge/method/ontology.md` *(원본으로 채움)*
- **R4 후크 주입** — 사용자 `hookNote`를 차별화 지점에 반영(엔진은 후보만 제안, 강요하지 않음).
- **R5 검증** — `engine/schema.ts`의 `validateStructure()`로 무결성 체크(블록 수·반전점·적대자·B스토리).
- **R6 출력** — 스키마 JSON으로 직렬화.

## 출력 계약 (Output) — `engine/schema.ts` 준수
`Story { logline, premise, genre, target, tone, characters[], blocks[24], reversalPointIndex, notes[] }`
- 응답은 **JSON만** 반환(설명·마크다운 금지). 파싱 후 `validateStructure()`로 검증한다.

## 방법론 데이터 (반드시 원본으로)
- `knowledge/method/24block.md` — 24블록 각 기능
- `knowledge/method/ontology.md` — 욕망 4축·신호 위계
- **이 슬롯이 비면 엔진은 일반 작법으로 퇴화한다. 임의 창작 금지.**
